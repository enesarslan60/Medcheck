# Medcheck — Drug Interaction Checker

Full-stack template for a drug interaction checker. Users search for medications,
add several to a list, and the system returns interaction details and a
plain-language explanation generated by Claude.

## Architecture

- **Backend** — Java 21, Spring Boot 3, Spring Data JPA, H2 (in-memory), Maven
- **Frontend** — Angular 17 (standalone components), Angular Material
- **LLM** — Anthropic Claude API (`claude-sonnet-4-20250514`)
- **External data** — [OpenFDA Drug Label API](https://open.fda.gov/apis/drug/label/) (no key required)

```
Medcheck/
├── backend/    Spring Boot application
└── frontend/   Angular application
```

### Layered backend structure

```
com.drugchecker
├── config/        CORS + RestTemplate beans
├── controller/    REST endpoints
├── service/       Business logic (Drug, Interaction, LLM, OpenFDA)
├── repository/    Spring Data JPA repositories
├── model/         JPA entities (Drug, Interaction)
└── dto/           Request/response DTOs (entities are never exposed)
```

## Running the project

### Prerequisites

- Java 21
- Maven 3.9+
- Node.js 18+ and npm

### 1. Backend

```bash
cd backend
# (optional) set your Anthropic API key
export ANTHROPIC_API_KEY=sk-ant-...
mvn spring-boot:run
```

The API starts on `http://localhost:8080` and the H2 console is available at
`http://localhost:8080/h2-console` (JDBC URL: `jdbc:h2:mem:drugdb`, user `sa`,
empty password).

If the Anthropic API key is not configured, the LLM service falls back to a
fixed message — the app still works offline using only the local seed data and
OpenFDA.

### 2. Frontend

```bash
cd frontend
npm install
ng serve
```

Open `http://localhost:4200`.

CORS is configured on the backend so requests from `localhost:4200` are
permitted automatically.

## REST API

| Method | Path                              | Description                             |
| ------ | --------------------------------- | --------------------------------------- |
| GET    | `/api/drugs`                      | List all drugs in the local DB          |
| GET    | `/api/drugs/search?name={q}`      | Autocomplete search                     |
| GET    | `/api/drugs/openfda?name={q}`     | Live drug info from OpenFDA             |
| POST   | `/api/interactions/check`         | Body: `{ "drugNames": ["A", "B", ...] }` |

## Interaction lookup pipeline

`InteractionService.checkInteractions()` enumerates every pair from the input
list and applies the following priority logic:

1. **Local cache (H2)** — return immediately if the pair is already stored.
2. **OpenFDA** — call `OpenFDAService.searchInteractions()` against
   `https://api.fda.gov/drug/label.json` for the drug pair.
3. **LLM explanation** — when OpenFDA returns text, hand it to
   `LLMService.generateExplanation()` for a non-technical summary.
4. **Persist** — newly fetched interactions are saved into H2 so the same pair
   is never fetched twice.
5. **No data** — if both sources are empty, a "No known interaction found"
   result is returned.

## OpenFDA + caching notes

- OpenFDA is the primary upstream source for drug interactions in this app.
- H2 acts as a local cache: every successful OpenFDA fetch is persisted, so
  subsequent checks for the same pair return instantly.
- **No API key is required.**
- Public rate limits: **1000 requests per day** without a key, **120 requests
  per minute** with a free key (set in `application.properties` if needed).

## LLM integration

`LLMService` posts to `https://api.anthropic.com/v1/messages` with model
`claude-sonnet-4-20250514` and the following system prompt:

> You are a medical assistant helping non-medical users understand drug
> interactions. Explain the following drug interaction in simple, clear
> language. Always recommend consulting a doctor for serious interactions.
> Never invent medical facts — only explain what is provided to you.

If the API call fails for any reason, the fallback message is:

> Explanation currently unavailable. Please consult your doctor or pharmacist.

## Sample data

`backend/src/main/resources/data.sql` seeds 10 drugs and 5 interactions
(1 SEVERE, 2 MODERATE, 2 MILD). This data is for offline testing and
development; real interactions are fetched live from OpenFDA.
